# Continuous Deployment & Infrastructure

This document outlines the deployment architecture, CI/CD pipeline, and hosting infrastructure for the portfolio.

---

## 1. CI/CD Architecture

Deployments are fully automated via GitHub Actions on every push to the `main` branch.

```
git push origin main
       │
       ▼
GitHub Actions CI Runner (.github/workflows/deploy.yml)
       │
       ├── 1. Check out repository
       ├── 2. Setup Node.js 20 environment with npm caching
       ├── 3. Install dependencies (`npm ci`)
       ├── 4. Strict Typecheck (`npm run typecheck`)
       ├── 5. Production Build (`npm run build`)
       └── 6. Deploy static artifacts to GitHub Pages
```

---

## 2. GitHub Pages SPA Routing

GitHub Pages does not natively handle HTML5 pushState routing for Single Page Applications (SPAs).
- A custom `public/404.html` script intercepts unmapped paths and transparently redirects them back to the base path with the target query preserved.
- The `base: '/My_Portfolio/'` setting in `vite.config.ts` ensures all asset URLs resolve with root-relative paths.

---

## 3. Cache Invalidation Strategy

- Production assets generated by Vite include content hashes in filenames (`index-[hash].js`, `index-[hash].css`).
- Binary assets (e.g. `Madhu_S_Resume.pdf`) employ query-string timestamps (`?v=20261115`) to bust stale proxy or browser caches instantly.
